## 0. この表記が必要になる理由

**結論**: 特定商取引法に基づく表記が必要になる主因は、itch.io本体の投げ銭(Pay What You Want)
ではなく、**ゲーム内ジェム課金が当社自身のStripe決済であること**です。

itch.io本体の代金回収方式(itch.ioが回収するか、当社のStripe/PayPal等へ直接入るか)によって
本体分の販売者・表示義務の帰属は変わり得ますが、ジェム課金は
[autoload/backend_config.gd](../autoload/backend_config.gd) 15行目の`COMMERCE_API_BASE_URL`
(自社Cloudflare Workers `commerce-api`)経由で自社Stripeアカウントに代金が入る設計のため、
**配信チャネル(itch.io/Steam/Web)や本体の価格設定にかかわらず、ジェムの販売者は常に当社**です。
[EOS_LEGAL_REVIEW.md](EOS_LEGAL_REVIEW.md)や本ロードマップのPhase 4 P0-1では
「Steam経由販売ではValveが販売者になり表示義務がValve側に移る可能性がある」という論点を
別途整理していますが、**ジェム課金を自社決済で維持する限りこの論法は使えず**、
これがitch.io先行リリースにあたって本表記を必須項目とする根拠です。

## 2. 掲載場所の候補

本ドラフトでは掲載場所を確定しません。候補と各案の制約のみを整理します。

- **itch.ioストアページ本文の末尾**: 追加の実装なしで即座に掲載できるが、Steam版・Web版展開時に
  同じ文面をそれぞれのストア/サイトへ個別に貼る運用になる。
- **GitHub Pages上の静的ページ**: Web版と同じ配信基盤([README.md](../README.md)の
  GitHub Pages配信手順を参照)に1ページ追加する形。全チャネル共通のURLを1つ用意できる。
- **ゲーム内(設定画面・ショップ画面)**: `scenes/shop_screen.gd`等から`OS.shell_open()`で
  外部URLを開くリンクを追加する形(Phase 0のC-02購入確認モーダルと同じ領域)。

現状、EULA・プライバシーポリシーも含めいずれの文書もゲーム内・Web上のどこにも露出しておらず
(`docs/`配下のMarkdownのみ)、掲載導線の実装はプレースホルダ確定後の別作業とします
(詳細は`tag-game-ux-fix-roadmap.md`のPhase 5「対象外・保留」参照)。

## 3. 専門家に確認すべき論点

各論点のオーナー判断(2026-10-16〜25)を括弧内に記す。判断の詳細は Confluence「判断記録」と各 Jira チケット。

- 個人開発者が所在地・電話番号を広告・特商法表記上で省略できる例外(通信販売の特例)の適用可否。
  (KAN-14: 「請求があれば遅滞なく開示」の形で省略する前提で第1章を書いた。適用できるかを KAN-18 で確認する)
- itch.io側の代金回収方式(itch.ioが回収する場合/当社の決済アカウントへ直接入る場合)による、
  ゲーム本体分の表示義務の帰属。
- **ジェムが資金決済法上の「自家型前払式支払手段」に該当するか**。該当する場合、
  未使用残高が基準日(3月31日・9月30日)に1,000万円を超えると、財務局への届出義務が
  生じる可能性がある。特定商取引法の範囲外の論点だが、同じ課金設計から生じるため
  併せて確認する。(KAN-15: 「自家型・届出不要の規模」と整理する。表示すべき事項があるかを KAN-18 で確認する)
- itch.io 本体の代金回収方式は Collected by itch.io(Payouts)とした(KAN-62)。本体分の表示義務の帰属は
  これを前提に確認する。
- 総額表示(消費税込み)義務との整合。[autoload/currency_pack_catalog.gd](../autoload/currency_pack_catalog.gd)
  7行目のコメントが自認するとおり、`display_price`は「静的なフォールバック表示価格(概算)」
  であり、画面表示額とStripeの実請求額が一致していること・税込みであることの実確認が必要
  (`tag-game-ux-fix-roadmap.md`のPhase 5「ユーザーのみが行える操作」のStripe本番Price ID確認と
  合わせて実施)。(KAN-15: 実請求額をそのまま「税込」と表示する。一致の確認は本番 Price を作る KAN-26 で行う)
