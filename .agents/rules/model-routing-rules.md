# モデルとサブエージェントの使い分け（Antigravity / Gemini 向け）

作業の重さに合ったモデルを使うためのルールです。
Claude Code 側にも同じ考え方の判断基準があり（`~/.claude/skills/model-routing/SKILL.md`）、
**両方の AI で足並みをそろえるためのもの**です。

## 0. 最初に: できないこと

**あなたは、会話の途中で自分のモデルを切り替えられません。**
会話に使うモデルを選ぶのは**ユーザー**です（Antigravity のモデル選択）。

あなたにできるのは次の2つだけです。

1. **「この作業なら軽いモデルで足ります」とユーザーに伝えること**
2. **サブエージェントに、段（tier）を指定して仕事を振ること**

「軽いモデルに切り替えて続けます」とは言わないでください。**できません。**

## 1. 鉄則

> **サブエージェントを作るとき、モデルの段を必ず明示してください。**

`define_subagent` のモデルは、**指定しないと `inherit`（呼び出し元と同じ）**になります。
つまり **指定を省くことは「安く済ませる」ではなく「一番高いままにする」**ことです。

| 段 | 何に使うか |
| --- | --- |
| `flash_lite` | ごく軽い作業。一覧を作る・体裁をそろえる・転記する |
| `flash` | 調べ物・ファイルの読み込み・検索・レビューの下読み |
| `pro` | 執筆・設計・多段の計画・音楽/画像生成を伴う判断。深い推論が要るもの |
| `inherit` | 既定。**意図して選ぶとき以外は使わない** |

## 2. 委譲するかどうか

サブエージェントは**あなたの文脈を引き継ぎません**。必要なファイルを自分で読み直します。
つまり:

> **小さい仕事を委譲すると、自分でやるより高くつきます。**

### 委譲が得になる形

**「たくさん読んで、少しだけ返す」** — ここだけです。

| 形 | 例 | 段 |
| --- | --- | --- |
| 広く読んで場所を特定する | 「この設定はどこで読まれている?」 | `flash` |
| 事前資料の読み込み | ワークフローの「事前に読むもの」を要約させる | `flash` |
| 一覧・転記・体裁そろえ | 表の作成、書式の統一 | `flash_lite` |
| 分量のある執筆 | 作曲仕様書・設定資料 | `pro` |

### 委譲してはいけない形

- **ファイル2〜3個で済む調査** — コールドスタートのぶん、自分で読むほうが安い
- **直前の会話が前提になる仕事** — 説明を書くコストが、やるコストを超える
- **判断そのもの** — 結論を検証し直す羽目になり、二度手間になる

### 委譲する前に、出力を絞れないか考える

コマンドの出力が長いだけなら、**サブエージェントを出すより `grep` や `head` で絞るほうが安い**です。
数百行のログを丸ごと読み込まないでください。

## 3. 返ってきたものは検証する

**サブエージェントの報告を鵜呑みにしないでください。** もっともらしく書かれた誤りが混ざります。
**見ていないものは「見ていない」と書いてください。** これは委譲先にも同じことを求めてください。

## 4. 報告

作業の最後に、**何をどの段に振ったか**を1行で書いてください。
使用量は目に見えないので、書かないと判断材料が残りません。

例: 「事前資料の読み込みを `flash` のサブエージェントに、作曲・生成は本会話（pro）で行いました」

## 5. ワークフローごとの目安

各ワークフロー（`.agents/workflows/*.md`）の冒頭に **`## 使うモデル`** 節があります。
`/tag-*` を実行するときは、まずそこを読んでください。

一覧は [workflows/README.md](../workflows/README.md) にあります。
