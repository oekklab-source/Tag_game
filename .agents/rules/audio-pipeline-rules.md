# Tag_Game 音楽・SE 制作ルール

Tag_Game（`3D Chase Game`、マリオ風カラフルな160×160mマップのオンライン鬼ごっこ）の
BGM・SEを生成・変更するときの規約です。**Claude Code / Antigravity 共通**で適用します。

## 1. 現状（2026-09-14時点）

- `project.godot` に `[audio]` セクションは無く、`default_bus_layout.tres` も存在しません。
  つまり **Master バス1本のみが暗黙的に存在**します。
- `AudioStreamPlayer` / `AudioServer` を使った再生コードはリポジトリ全体で**ゼロ**です。
  BGM・SEは1つも実装されていません。
- UX修正ロードマップの H-07（設定画面）で、**マスター音量スライダーだけ先に用意されています**
  （`autoload/settings_manager.gd` の `master_volume` → `AudioServer.set_bus_volume_db()`）。
  今は鳴らす音が無いため見た目上の効果はありませんが、音源が実装され次第すぐ効きます。

## 2. 対象シーンと想定ムード（決め打ち、変更可）

| シーン | 用途 | ムードの目安 | 参考にする既存ゲーム音源 |
|---|---|---|---|
| `scenes/title.tscn`（タイトル）／ロビー待機中 | BGM（ループ） | ポップで明るい。マリオ風のカラフルな世界観に合わせる | マリオカート／マリオパーティ系（キャッチーで、長時間聴いても疲れないバランス） |
| `scenes/world.tscn`（鬼ごっこ本編） | BGM（ループ） | 緊張感・疾走感。逃走者・鬼どちらの視点でも聞いていて煽られる曲調 | Dead by Daylight／Propnight等、非対称対戦系の鬼視点BGM（UX監査で使った比較軸を流用） |
| `scenes/hud.tscn` の結果画面 | 短いSE／スティンガー | 「にげきった」「つかまえた」で明確に印象が変わるとなお良い（勝敗別は任意） | Fall Guys／Party Animals等、カジュアル系の勝敗スティンガー |

指定が無ければ、まず**タイトル/ロビーBGM**から着手すればよい。この表はWeb版Geminiでの
レビュー（下記8.参照）が主観チェックの比較対象として参照する正本でもある。Web版Geminiは
このファイルを直接読めないため、レビュー依頼文を作る際はClaude Codeが該当行をそのまま
転記する。

## 3. 品質基準（プロ品質）

客観チェック（尺・ループ境界・BPM/キーの一致）は**必要条件に過ぎず、十分条件ではありません**。
2026-09-14の実地レビューで、客観チェックのみに基づいた回答が「プロフェッショナル基準との
比較が無く浅い」との指摘を受けたため、以下を必須の評価基準として追加します。

- **実在の比較対象を具体的な曲名で挙げること**: ジャンルの雰囲気（例:「マリオカート系」）を
  挙げるだけでは不十分です。レビュー（Web版Gemini）は自身の知識にある実在のプロ作品を
  **具体的な曲名・作品名**で挙げ、その曲と比較してどうかを論じてください。
- **必須評価軸（3つ）**:
  1. **ミックス/マスタリング品質**: 周波数バランス、音圧、ダイナミクス、定位が、商用
     リリースされているゲーム音源と比べて見劣りしないか
  2. **アレンジの完成度**: メロディが記憶に残るか、展開に工夫があるか、長時間（ロビー待機等）
     聴いても飽きない構成になっているか
  3. **音色/サウンドデザインの品質**: プリセット感・安っぽさが無いか、音色の選択が楽曲の
     世界観に合っているか
- **一言判定の禁止**: 「悪くないと思います」のような主観の一言で終わらせず、上記3軸それぞれで
  具体的な指摘（良い点・改善点の両方）を書くこと。
- この基準は、Claude CodeがWeb版Gemini向けに**生成**依頼文を作るときにも適用する
  （生成段階からプロ品質を狙うことで、レビューでの手戻りを減らすため）。

## 4. フォーマット規約（この数値が正本）

| 項目 | 値 | 備考 |
|---|---|---|
| BGM形式 | **Ogg Vorbis (.ogg)** 推奨 | Godotのストリーミング・ループ機構と相性が良い |
| SE形式 | **.wav** | 短尺・即時再生向け |
| ループ | 開始・終了位置を**秒単位**で仕様書に明記 | Godot側の`AudioStreamOggVorbis`のループ設定に使う |
| 対象バス | Master（現状これ1本のみ） | 将来BGM/SE別バスに分ける場合はClaude Code側で判断する |

## 5. 出力先の分離（重要）

| 置き場 | 用途 | 誰が書くか |
|---|---|---|
| `docs/concept/audio/<用途>/SPEC.md` | 作曲仕様書(アイデア・BPM・キー・ループ秒など) | **Antigravity(Gemini)が自由に書いてよい** |
| `docs/concept/audio/<用途>/` の音声ファイル | 参考音声ファイル | **Web版Gemini**で生成し、ユーザーが保存(2026-09-14以降) |
| `docs/concept/audio/<用途>/REVIEW.md` | Web版Geminiによるレビュー結果 | **Claude Code**がユーザーから受け取った内容を転記 |
| `assets/` | ゲームに実際に組み込む最終アセット | **Claude Code側が精査・変換のうえ配置**。Antigravity/Web版Geminiは直接書かない |

- **`assets/` に音声ファイルを直接置かないでください。** `assets/`配下は現状 `character/` `gimmicks/` `props/`
  の3Dモデル(.glb)専用で、音声はまだ置き場所自体が無い状態です。統合方法（バス構成・AudioStreamPlayerの
  配置・`project.godot`の`[audio]`セクション新設など）はClaude Code側の判断に委ねてください。
- `docs/concept/audio/` 配下は AI・人間が自由に置いてよい参照資料置き場です（`docs/`直下は
  `DEPLOYMENT_CHECKLIST.md`等の正式ドキュメントのみなので、音楽の作業ファイルは必ず`concept/audio/`以下に収めること）。

## 6. 画像/テキストで求めるものが違う、と同じ構造を音声にも適用する

| 成果物 | 規格 | 用途 |
|---|---|---|
| **音声ファイル** | **参考品質でよい。最終ミックス・ループ処理の完成度は問わない** | 曲調・テンポ・雰囲気の参考 |
| **テキスト仕様書** | BPM・キー・ループ秒・尺・使用シーン・ムードを**厳密に**明記 | Claude Code が実装（ストリーミング設定・音量バランス等）するための指示 |

「まだラフだから」を理由に音声生成をあきらめないでください。生成ツールが本当に使えないときだけ、
その旨をはっきり伝えてテキストのみで代替してください。

## 7. 守ること

- **`.gd` / `.tscn` / `project.godot` は変更しないでください**。ゲームへの組み込みはClaude Code側が行います。
- **`assets/` には直接音声を置かない**（上記5.参照）。
- **既にファイルがある場合は上書きせず、日付見出しを付けて末尾に追記**してください。
- 応答は日本語で行ってください。

## 8. Claude Codeの組み込みゲート

対象ディレクトリ(`docs/concept/audio/<用途>/`)に`REVIEW.md`が無い、またはPASS判定でない
参考音源は、**Claude Codeはゲームへ組み込みません**（`assets/`への変換・配置を行いません）。

レビューは2026-09-14以降、**Web版Gemini**（gemini.google.com）で行います
（`.agents/workflows/tag-music-review.md`参照。Antigravityの`/tag-music-review`としては
もう実行しません）。Web版Geminiの方が音声を正確に評価できることが実地で確認できたため、
音源の生成・レビューは両方ともWeb版Geminiへ移管しました。SPEC.mdの執筆（曲のアイデア・
仕様）は引き続きAntigravity（`/tag-music`）が担当します。Web版Geminiはこのリポジトリの
ファイルを読めないため、Claude Codeが`SPEC.md`と本ファイルの比較対象表（上記2.）・
品質基準（上記3.）を埋め込んだ自己完結型の依頼文を用意し、ユーザーがそれをWeb版Geminiの
**新規チャット**（作曲や前回レビューの続きにしない。自己採点バイアスとアンカリングを
避けるため）に貼り付けて実行します。結果はClaude Codeが`REVIEW.md`へ転記します。

実例: 2026-09-14に生成されたタイトル/ロビーBGMの参考音源(`docs/concept/audio/title_bgm/`)は、
このゲートが整備される前に生成されたもの（`REVIEW.md`が無く、しかも尺が仕様書の指定30秒〜1分
に対し実測11秒しか無かった）だったため、Claude Codeは組み込みを見送っている。また同日、
上記3.の品質基準が整備される前の依頼文によるレビューは「プロフェッショナル基準との比較が
無く浅い」との指摘を受けたため、品質基準を追加のうえ新規チャットで再レビューを行っている。
