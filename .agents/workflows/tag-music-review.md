# Tag_Game 劇伴・SE レビューワークフロー（2026-09-14以降: Web版Geminiへ移管）

**このワークフローはもはやAntigravityの `/tag-music-review` としては実行しません。**
Web版Gemini（gemini.google.com）の方が音声を正確に評価できることが実地で確認できたため、
参考音源のレビューはWeb版Geminiで行うことに変更しました。以下は現在の実際の手順です。

- **レビューの実行主体**: **Web版Gemini**（ユーザーが手動でブラウザ/アプリを開いて実行）
- **依頼文の作成・結果の`REVIEW.md`への転記**: **Claude Code**が担当
  （Web版Geminiはこのリポジトリのファイルを読めないため、対象ディレクトリの`SPEC.md`の
  内容と、下記「比較対象の参考ゲーム音源」表を**依頼文に直接埋め込んで**渡す。
  レビュー対象の音声ファイルはユーザーがWeb版Geminiの会話に添付する）

**なぜ作曲した会話とは別主体でレビューするか**: 自分が作った直後の音源を自分で採点すると
甘くなりがちなため（Claude Code側の`second-opinion`エージェントが、経緯を知らない別視点で
レビューするのと同じ理由）。SPEC.mdを書いたAntigravity会話とは別の、Web版Geminiという
別主体でレビューすることでこれを担保する。

Claude Codeは、対象ディレクトリに`REVIEW.md`が無い、またはPASS判定でない参考音源を
**ゲームへ組み込みません**（`.agents/rules/audio-pipeline-rules.md`の組み込みゲート参照）。

## 事前に読むもの（Claude Codeが依頼文を組み立てる際に参照）

1. レビュー対象ディレクトリ（`docs/concept/audio/<用途>/`）の `SPEC.md`
2. `.agents/rules/audio-pipeline-rules.md` の「## 2. 対象シーンと想定ムード」表
   （参考にする既存ゲーム音源の基準はここに一本化されている。Web版Gemini向け依頼文には
   この表の該当行をそのまま転記する）
3. `.agents/rules/audio-pipeline-rules.md` の「## 3. 品質基準（プロ品質）」
   （プロ品質比較で必須の3軸の正本。同じくWeb版Gemini向け依頼文に転記する）

## 手順

1. 対象を決める（指定が無ければ最後に生成されたディレクトリ）。
2. Claude Codeが `SPEC.md` の内容と比較対象の参考ゲーム音源（上記表）を埋め込んだ、
   自己完結型のレビュー依頼文を作成する。
3. ユーザーがWeb版Geminiの**新規チャット**にその依頼文を貼り付け、対象の音声ファイルを
   添付してレビューを依頼する。
4. Web版Geminiの回答（客観チェック・主観チェック・判定・改善指示）をユーザーがClaude Codeに
   共有する。
5. Claude Codeが、その内容を次のフォーマットのまま `docs/concept/audio/<用途>/REVIEW.md`
   へ追記する。**既存ファイルがあれば上書きせず、日付見出しを付けて追記**する
   （`/tag-music` と同じ規約）。

Web版Geminiに求めるチェック内容（依頼文に含める）:

- **客観チェック**（いずれか未達なら即 NEEDS-REVISION）:
  - 尺が `SPEC.md` の指定レンジ内に収まっているか
    （反省: 2026-09-14生成のタイトル/ロビーBGMは指定30秒〜1分に対し実測11秒だった。
    このチェックは必ず実施すること）
  - ループ開始/終了点の境界でノイズ・不自然な音量変化・不自然な繋ぎ目が無いか
  - BPM/キーが `SPEC.md` の指定と概ね一致しているか
- **客観チェックはあくまで必要条件であり、これだけでPASSにしないこと。**
  （反省2: 2026-09-14、客観チェックのみに基づいた回答が「プロフェッショナル基準との
  比較が無く浅い」との指摘を受けた。以下のプロ品質比較を必ず行うこと）
- **プロ品質比較**（`.agents/rules/audio-pipeline-rules.md` の「## 3. 品質基準（プロ品質）」
  が正本。依頼文にはこの3軸を明記する）:
  1. **ミックス/マスタリング品質**: 周波数バランス・音圧・ダイナミクス・定位が、商用
     リリースされているゲーム音源と比べて見劣りしないか
  2. **アレンジの完成度**: メロディが記憶に残るか、展開に工夫があるか、長時間聴いても
     飽きない構成か
  3. **音色/サウンドデザインの品質**: プリセット感・安っぽさが無いか
  いずれも**ジャンルの雰囲気だけでなく、自身の知識にある実在のプロ作品を具体的な曲名で
  挙げて**比較すること。「悪くないと思います」のような一言判定は禁止し、3軸それぞれで
  具体的な指摘（良い点・改善点の両方）を書くこと。

## 出力フォーマット（REVIEW.md）

```markdown
## <日付> レビュー（Web版Gemini）

**判定**: PASS / NEEDS-REVISION

### 客観チェック
- 尺: ...
- ループ境界: ...
- BPM/キー: ...

### プロ品質比較
- 比較対象（具体的な曲名・作品名）: ...
- ミックス/マスタリング品質: ...
- アレンジの完成度: ...
- 音色/サウンドデザインの品質: ...

### 改善指示（NEEDS-REVISIONの場合のみ）
...
```

## 守ること

- レビューは必ずWeb版Geminiの**新規チャット**で行う（既存の作曲用チャットの続きにしない）。
- `.gd` / `.tscn` / `project.godot` は変更しないでください（`/tag-music` と同じ）。
- `REVIEW.md` は上書きせず、既存があれば日付見出しを付けて末尾に追記してください。
- 応答は日本語で行ってください。
