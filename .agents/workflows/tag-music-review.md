# Tag_Game 劇伴・SE レビューワークフロー

`/tag-music` で生成された参考音源(`docs/concept/audio/<用途>/`)を、作曲した会話とは
**別の(新規)Antigravity会話**でレビューし、Claude Codeがゲームへ組み込んでよいか判定する。

**なぜ別会話が必要か**: 作曲した会話の続きでレビューすると、自分が作った直後の音源を
自分で採点することになり甘くなりがちです（Claude Code側の`second-opinion`エージェントが、
経緯を知らない別視点でレビューするのと同じ理由）。必ず新しいAntigravity会話を開くか、
ウィンドウを再読み込みしてから実行してください。

Claude Codeは、対象ディレクトリに`REVIEW.md`が無い、またはPASS判定でない参考音源を
**ゲームへ組み込みません**（`.agents/rules/audio-pipeline-rules.md`の組み込みゲート参照）。

## 使うモデル

| | |
| --- | --- |
| **この会話を開く段** | **pro** — 音楽的な品質判断・専門ゲーム音源との比較には深い推論が要るため |
| **サブエージェントへ投げる部分** | 対象ディレクトリ・`audio-pipeline-rules.md`の事前読み込みを **flash** で |

**サブエージェントの段は必ず明示してください。** 省くと `inherit`（この会話と同じ段）になり、
軽い調べ物まで重いモデルで走ります。判断基準の正本は `.agents/rules/model-routing-rules.md` です。

## 事前に読むもの

1. レビュー対象ディレクトリ(`docs/concept/audio/<用途>/`)の音声ファイルと `SPEC.md`
2. `.agents/rules/audio-pipeline-rules.md` の「## 2. 対象シーンと想定ムード」表
   （参考にする既存ゲーム音源の基準はここに一本化されている。ここで重複して書かないこと）

## 手順

1. 対象を決める（指定が無ければ最後に生成されたディレクトリ）。
2. 音声ファイルを聴き、`SPEC.md` を読む。
3. **客観チェック**（いずれか未達なら即 NEEDS-REVISION。主観チェックより先に判定できる）:
   - 尺が `SPEC.md` の指定レンジ内に収まっているか
     （反省: 2026-09-14生成のタイトル/ロビーBGMは指定30秒〜1分に対し実測11秒だった。
     このチェックは必ず実施すること）
   - ループ開始/終了点の境界でノイズ・不自然な音量変化・不自然な繋ぎ目が無いか
   - BPM/キーが `SPEC.md` の指定と概ね一致しているか
4. **主観チェック**（「良い/悪い」で終わらせず、具体的な比較対象を挙げて論じる）:
   `audio-pipeline-rules.md` の対象シーン表にある参考ゲーム音源と比べて、テンポ感・
   キャッチーさ・ミックス（音圧・音の厚み）の完成度で見劣りしないかを論じる。
   ロビーBGMのように長時間再生が前提のものは「長く聴いても疲れないか」も評価する。
5. 判定（PASS / NEEDS-REVISION）と、具体的な改善指示（NEEDS-REVISIONの場合、次の
   `/tag-music` 実行で何をどう直すべきか）を `docs/concept/audio/<用途>/REVIEW.md` へ
   追記する。**既存ファイルがあれば上書きせず、日付見出しを付けて追記**する
   （`/tag-music` と同じ規約）。

## 出力フォーマット（REVIEW.md）

```markdown
## <日付> レビュー

**判定**: PASS / NEEDS-REVISION

### 客観チェック
- 尺: ...
- ループ境界: ...
- BPM/キー: ...

### 主観チェック
（参考ゲーム音源との比較を具体的に）

### 改善指示（NEEDS-REVISIONの場合のみ）
...
```

## 守ること

- **作曲した会話の続きではなく、別の(新規)Antigravity会話で実行してください。**
- `.gd` / `.tscn` / `project.godot` は変更しないでください（`/tag-music` と同じ）。
- `REVIEW.md` は上書きせず、既存があれば日付見出しを付けて末尾に追記してください。
- 応答は日本語で行ってください。
