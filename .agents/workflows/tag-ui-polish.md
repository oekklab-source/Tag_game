# Tag_Game UIポリッシュ実装ワークフロー

**このワークフローは単独では動きません。** 必ず対になるタスク指示書
（`.agents/workflows/tasks/<名前>.md`）とセットで実行してください。指示書が無い状態でこの
ワークフローだけを実行しないでください。

`.agents/rules/coexistence-rules.md`の「コード・シーンへの不介入」原則の**限定的な例外**として
新設しました。音楽委譲（`/tag-music`）と違い、このワークフローは実際に `.gd` / `.tscn` を編集します。
そのぶん、対象タスクはClaude Codeが**設計判断を終えたうえで**、変更内容を1行単位まで確定させた
ものに限られます。ここでの仕事は「決められたことを正確に打ち込み、正しく検証すること」です。

## 使うモデル

`pro` 推奨（コード編集を伴うため）。判断基準の正本は `.agents/rules/model-routing-rules.md`。

## 事前に読むもの

1. **対になるタスク指示書**（`.agents/workflows/tasks/<名前>.md`）— 対象ファイル・変更内容・
   触ってはいけないものが全てここに書かれています。
2. `CLAUDE.md` の「RPC を変更するときの鉄則」節と「テストの流し方」節。
3. `.agents/rules/coexistence-rules.md` の「例外: `.gd` / `.tscn` への限定的な介入」節。

## 手順

1. タスク指示書に列挙された対象ファイルを読み、現在の内容が指示書の前提（引用しているコード・
   行番号）と一致しているか確認する。**ズレていたら実装を止めてユーザーに確認する**
   （ファイルが指示書作成後に変更された可能性があるため、推測で読み替えない）。
2. 指示書に明記された変更のみを行う。指示書にない改善・リファクタ・見た目の追加調整はしない
   （範囲外の変更はスコープ違反）。
3. 指示書が指定する回帰テストを `tools/run_headless_test.ps1 res://tests/<name>.tscn` で実行する。
   全て指示書の期待通り（多くの場合「既存の結果から変化なし」）であることを確認する。
4. 見た目の変更（色・レイアウト等）は、可能なら既存のwindowedスクリーンショット手段
   （`tests/uishot.tscn` など）や `godot --editor` での目視で確認する。新しい一時検証スクリプトを
   書く場合は、**必ずheadlessドライラン（構文・シーンload/instantiateの成否だけ確認、画像は撮れない）
   → windowed本番実行の順**を守ること。`RenderingServer.frame_post_draw` を待つパターンの
   スクリプトはheadlessでは永久に発火しないため、これをheadlessで動かそうとしないこと。
   一時検証スクリプトはコミット前に必ず削除する（そもそも今回はcommitしないので、作業ツリーに
   残さず作業完了時点で削除する）。
5. Godotプロセスを自分で終了させる必要が生じた場合、**自分が起動したプロセスのPIDのみ**を対象に
   すること。CPU使用量などの状況証拠だけで「これは自分のプロセスだ」と判断しない
   （このプロジェクトでは実際に別セッションのエディタを誤って終了させかけた事故が記録されている）。
6. `.ps1` ファイルを新規に書く場合はUTF-8 BOM付きで保存すること（Windows PowerShell 5.1が
   BOM無しの日本語を含むスクリプトをパースエラーにするため）。`--quit-after` は必ず `--` より
   **前**（エンジン側オプション）に置くこと。`--` より後ろに置くとユーザー引数側に渡ってしまい、
   エンジンには一切効かず、プロセスがハングしたまま残り続ける事故につながる。
7. `git add` / `git commit` / `git push` は**行わない**。作業ツリーに変更を残したまま、完了レポートを
   作成する。

## 完了レポート

作業完了後、以下を含む短いレポートをタスク指示書と同じ `.agents/workflows/tasks/` フォルダに
`<名前>-report.md` として保存する（コードファイルではないためこの例外の対象外、通常通り
Antigravityが直接書いてよい）:

- 変更したファイル一覧
- 実行した回帰テストとその結果
- 見た目の変更を確認できたか（windowed確認 済み/未実施のいずれか、未実施ならその理由）
- 指示書通りに進められなかった点、判断が必要だった点（あれば。無ければ「特になし」と明記）
- 「未commit・未push」であることの明記

## 守ること（再掲）

- タスク指示書に無いファイルは変更しない。
- `@rpc` が付いた関数のメソッド名・シグネチャ・ノードパス、`PROTOCOL_VERSION`
  （`autoload/game_manager.gd`）は、指示書が明示的に許可していない限り変更しない。
- `git commit` / `git push` は行わない。
- 応答は日本語で行う。
