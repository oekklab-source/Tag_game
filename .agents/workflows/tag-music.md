# Tag_Game 劇伴・SE 作曲ワークフロー

Tag_Game（マリオ風カラフルな160×160mマップのオンライン鬼ごっこ）には、現時点で
**BGM・SEが1つも実装されていません**（`project.godot`に`[audio]`セクション無し、
`AudioStreamPlayer`系のコードもリポジトリ全体でゼロ）。UX修正ロードマップのH-07で、
設定画面にマスター音量スライダーだけが先に用意されています──**音が来るのを待っている状態**です。

## 使うモデル

| | |
| --- | --- |
| **この会話を開く段** | **pro** — 曲調・構成の判断が要り、音声生成も伴うため |
| **サブエージェントへ投げる部分** | 「事前に読むもの」の読み込みと要約を **`flash`** で |

**サブエージェントの段は必ず明示してください。** 省くと `inherit`（この会話と同じ段）になり、
軽い調べ物まで重いモデルで走ります。判断基準の正本は `.agents/rules/model-routing-rules.md` です。

## 事前に読むもの

1. `.agents/rules/audio-pipeline-rules.md` — フォーマット規約と出力先の規約（**必読**）
2. `README.md` の冒頭〜「## ルール」「## マップ」 — ゲーム全体の世界観（カラフル・ポップ、
   非対称の索敵、緊張感のある鬼ごっこ）
3. `project.godot` — 現在の音設定（`[audio]`セクションが無いことの確認。無ければ新設の必要は
   Claude Code側の判断に委ねる）
4. 対象シーンの雰囲気を掴むための `scenes/title.tscn`、`scenes/hud.tscn`
   （既存のコンセプトアート・参考資料が`docs/concept/`にあれば合わせて読む）

## 対象（指定が無ければ 1 のタイトル/ロビーBGMだけ）

1. **タイトル/ロビーBGM** — ポップで明るいループ曲。プレイヤーが部屋を作って待っている間に流れる
2. **鬼ごっこ本編BGM** — 緊張感・疾走感のあるループ曲。逃走者・鬼どちらの視点でも聞いていて煽られる曲調
3. **結果画面SE/スティンガー** — 「にげきった」「つかまえた」の短い効果音（勝敗別は任意）

## 2026-09-14 更新: 音声の生成・レビューはWeb版Geminiへ移管

Web版Gemini（gemini.google.com）の方が音声を正確に評価・生成できることが実地で確認できたため、
**実際の音声ファイルの生成とレビューはこのAntigravityワークフローでは行いません。**
このワークフロー（`/tag-music`）が担うのは**仕様書（`SPEC.md`）の執筆**までです
（本ゲームの世界観・シーン構成を深く理解しているAntigravityが、曲調・構成のアイデアを
考える部分は引き続きここが担当します）。

新しい役割分担:

| 工程 | 担当 |
|---|---|
| 曲のアイデア・仕様書（`SPEC.md`）の執筆 | **Antigravity**（このワークフロー） |
| 参考音声ファイルの生成 | **Web版Gemini**（ユーザーが手動で実行） |
| 音声のレビュー（PASS/NEEDS-REVISION判定） | **Web版Gemini**（ユーザーが手動で実行） |
| Web版Gemini向け依頼文の作成・`SPEC.md`/`REVIEW.md`への転記・ゲームへの組み込み | **Claude Code** |

## 手順

1. 対象を決める
2. 実装用の仕様（BPM・キー・ループ開始/終了秒・尺・使用シーン・ムード）を**テキストで**
   厳密にまとめる（曲調イメージが伝わる音声ファイルをここで生成する必要はない。
   Claude Codeが`SPEC.md`の内容を元にWeb版Gemini向けの依頼文を用意し、実際の生成は
   そちらで行う）
3. `docs/concept/audio/<用途>/`（例: `docs/concept/audio/title_bgm/`）の`SPEC.md`に
   保存し、何のための曲か、どのシーンのどこで流す想定かを書く
4. 執筆後、Claude Codeに引き継いでください。Claude CodeがWeb版Gemini向けの生成・レビュー
   依頼文を用意します。`REVIEW.md` が PASS になるまで、Claude Codeはこの音源をゲームに
   組み込みません（`.agents/rules/audio-pipeline-rules.md` の組み込みゲート参照）。
   NEEDS-REVISION の場合、`REVIEW.md`の改善指示を踏まえて`SPEC.md`を改訂するところから
   このワークフローに戻ってきます。

## テキスト仕様で求めるもの（重要）

| 成果物 | 規格 | 用途 |
|---|---|---|
| **テキスト仕様書（`SPEC.md`）** | BPM・キー・ループ秒・尺・使用シーン・ムードを**厳密に** | Web版Geminiでの生成指示、Claude Codeが実装するときの指示の両方を兼ねる |

## 守ること

- **`assets/` には置かない**。ゲームへの組み込み（バス構成・再生コード・シーンへの配置）は
  Claude Code側がまとめて行います。ここでは`docs/concept/audio/`までです
- コードやシーンファイル（`.gd` / `.tscn` / `project.godot`）は変更しないでください
- **既にファイルがある場合は上書きせず、日付見出しを付けて末尾に追記**してください
- 応答は日本語で行ってください
